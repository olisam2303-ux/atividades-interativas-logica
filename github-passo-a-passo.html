Salvando seu trabalho no GitHub

Guia de apoio — vale para todas as atividades de Python
Tempo: 15 min na primeira vez Depois: 2 min por entrega Ferramenta: VS Code ou o site do GitHub
1. Criar a conta 2. Caminho A — pelo VS Code 3. Caminho B — pelo site 4. Cuidados
POR QUE

Para que serve isso

O GitHub é onde programadores guardam e compartilham código. Em vez de mandar o arquivo por e-mail e perder a conta de qual é a versão mais nova, o trabalho fica num endereço fixo, com o histórico de tudo que vocês mudaram e quando. É assim que se trabalha na profissão — e é por isso que a entrega das atividades de Python passa por lá.

Há dois caminhos. O A é pelo VS Code e é o mais prático no dia a dia, mas depende de o computador ter o Git instalado. O B é pelo site do GitHub, arrastando os arquivos: funciona em qualquer máquina, sem instalar nada. Se o A travar, o B resolve.
PASSO A PASSO

1. Criando a conta

1
Tentem primeiro com o e-mail institucional.

Entrem em github.com/signup e usem o e-mail da escola. Se o cadastro for até o fim e o e-mail de confirmação chegar, está resolvido: sigam para o passo 3.

Atenção: A rede da escola costuma bloquear a associação do e-mail institucional com serviços de fora. Se o cadastro for recusado, ou se o e-mail de confirmação não chegar, não insistam — passem para o passo 2.
2
Se o institucional não funcionar, criem um Gmail com o seu RA.

Criem uma conta em gmail.com no formato RA + sp, assim: 1234567890sp@gmail.com, trocando pelo seu número de RA. É esse número no endereço que permite ao professor saber de quem é cada entrega — sem ele, o trabalho chega sem dono. Com o Gmail criado, voltem ao github.com/signup e cadastrem-se com ele.

Atenção: Nada de apelido no endereço. O nome de usuário do GitHub também fica público e aparece no link do trabalho: usem o RA ou o nome e o sobrenome.
3
Anotem o nome de usuário.

É ele que forma o endereço do seu trabalho: github.com/seu-usuario/nome-do-repositorio. Esse endereço é o que vocês vão colar no AVA.

Atenção: Uma conta por aluno, mesmo em atividades de dupla. Quem for entregar cria o repositório e adiciona o colega depois.
CAMINHO A

2. Publicando pelo VS Code

O VS Code já vem com a integração do GitHub embutida: dá para publicar sem sair do editor.

4
Abram a pasta do trabalho no VS Code.

Arquivo → Abrir Pasta e escolham a pasta onde estão os arquivos .py da atividade. O VS Code passa a mostrar todos os arquivos no painel da esquerda.

5
Abram o painel de Controle do Código-Fonte.

É o terceiro ícone da barra lateral esquerda — três bolinhas ligadas por linhas — ou o atalho Ctrl + Shift + G. Vai aparecer o botão Publicar no GitHub ou Inicializar Repositório.

Atenção: Se aparecer a mensagem “Instalar Git”, o computador não tem o Git. Não tem problema: pulem para o Caminho B, pelo site.
6
Cliquem em Publicar no GitHub.

O VS Code abre o navegador para vocês entrarem na conta e autorizarem. Depois ele pergunta o nome do repositório e se ele será público ou privado. O nome precisa identificar a tarefa: logica-semana09-turma1A. Escolham Public — é obrigatório: é assim que o professor abre o trabalho pelo link, sem depender de convite.

7
Escrevam a mensagem do commit.

Cada vez que vocês salvam uma versão no GitHub, isso se chama commit, e todo commit leva uma mensagem curta dizendo o que mudou. Escrevam algo útil — “robô chef com o laço for funcionando” — e não “teste” ou “aaa”. É esse histórico que mostra o trabalho de vocês ao longo da aula.

8
Nas próximas vezes: alterar, commitar, sincronizar.

Depois de mexer no código: voltem ao painel de Controle do Código-Fonte, cliquem no + ao lado de cada arquivo alterado, escrevam a mensagem, cliquem em Commit e depois em Sincronizar Alterações. Só depois de sincronizar é que o trabalho está no GitHub de verdade.

CAMINHO B

3. Publicando pelo site

Use este caminho se o VS Code pedir para instalar o Git, ou se preferir um jeito mais direto.

9
Criem o repositório pelo site.

Já logados, cliquem no + no canto superior direito → New repository. O nome precisa identificar a tarefa: logica-semana09-turma1A. Marquem Public — obrigatório — e cliquem em Create repository.

10
Subam os arquivos arrastando.

Na página do repositório recém-criado, cliquem em uploading an existing file — ou em Add file → Upload files. Arrastem os arquivos .py da pasta para a área indicada.

11
Escrevam a mensagem e confirmem.

No campo de baixo, escrevam o que está sendo enviado e cliquem em Commit changes. Pronto: os arquivos estão no GitHub, sem instalar nada no computador.

Atenção: Para atualizar depois, é o mesmo caminho: Add file → Upload files, arrastando a versão nova por cima.

CUIDADOS

4. Antes de deixar público

Não subam dados pessoais.Nada de CPF, endereço, telefone ou foto de documento dentro dos arquivos. O repositório público é visível para qualquer pessoa da internet.
Senha nenhuma dentro do código.Se a atividade pedir uma senha de exemplo, use uma fictícia. Senha de verdade em repositório é um problema de segurança clássico — e vocês vão estudar isso.
O que entra é o código, não o relatório.O PDF gerado pela página da atividade continua indo para o AVA. No GitHub vai o programa.
CONFIRA

Checklist da entrega

✓ Tentamos o e-mail institucional primeiro; se não deu, criamos o Gmail com o RA (ex.: 1234567890sp@gmail.com).
✓ O repositório tem um nome que diz a disciplina, a semana e a turma.
✓ Os arquivos .py aparecem na página do repositório.
✓ Cada commit tem uma mensagem que explica o que mudou.
✓ O repositório está público — dá para abrir o link numa janela anônima e ver os arquivos.
✓ O link do repositório foi colado na entrega do AVA.
